# Kazumi 本地画质助手

独立运行的 Windows 本地工具：读取你已安装的 Kazumi 网站规则，搜索同一部番剧，先筛选最高分辨率和规格候选，再对不同网站的同一集取样，估计画质并排列来源。

它不修改 Kazumi 源码、安装文件或规则文件。原项目可以继续正常拉取 main 更新。本工具自身的代码维护在这个独立仓库。

## 在这台电脑上使用

工作目录：`D:\git\Kazumi-image-quality`。

1. 双击 `start.cmd`，或使用不显示终端窗口的 `启动画质助手.vbs`。
2. 浏览器打开 `http://127.0.0.1:18765`。默认选择自动发现的非空 Kazumi 规则文件。
3. 输入番剧名称，点击“搜索来源”。默认“智能比较”会搜索全部已配置规则。确认每个网站选中的是同一部、同一季；唯一规范化同名匹配会自动预选，明确的“第二季 / 第2季 / Season 2”等季号可对应。
4. 确认至少两个网站，点击“开始画质检测”。集数留空时自动选择覆盖网站最多的最早一集，也可指定集号。智能模式先排除低分辨率，按规格选出最多三个不同网站，再由模型比较共同画面。需要让不同分辨率的全部来源参与模型比较时，可选择“全来源模型快速”或“全来源模型完整”；这两种模式也允许自行勾选搜索规则。
5. 查看网站及线路排名，点击“打开”前往源站播放。工具不能在未修改 Kazumi 的情况下为它添加内部按钮。

重复启动只会打开已有页面。刷新页面可恢复正在运行的检测；服务重启后可展示最近保存的结果摘要，需要重新搜索才能再次检测。关闭浏览器不会停止本地服务；需要退出时双击 `stop.cmd` 或 `停止画质助手.vbs`。停止会结束本工具的任务和子进程，不会结束 Kazumi。

从其他模式切入智能模式后，需要重新搜索，确保覆盖全部规则；不能直接复用仅搜索部分网站的旧结果。

## 智能筛选规则

1. **先保留最高分辨率。** 读取各线路实际视频规格，以宽度乘高度的像素面积确定最高档。较低档直接排除，跳过体积估算、画面取样和模型评分，不因低档码率更高而保留。最高档只有一个网站时，只展示筛选结果，不生成跨站冠军。
2. **在相近规格内预选。** 同编码、相近帧率的来源按可用码率粗排；不同编码或帧率分组轮流提供候选，避免把 H.264、HEVC 等直接按同一个码率门槛硬排。每个网站规则最多保留一条线路，首轮最多三个不同网站。帧率更高、文件更大均不直接等于最终画质更高。
3. **区分视频码率与总码率。** 优先使用纯视频码率；缺失时参考大小与时长换算的平均码率，再回退到可用容器码率。只有音轨唯一且音频码率已知时才扣除音频，所得结果仍标为估算；否则保留总码率口径，不冒充纯视频码率。无法取得的数据保留为未知，不填零。
4. **只对候选进行模型比较。** 匹配三个共同正文位置，每个位置核验三个相邻画面，最终按 MUSIQ 评分统一排名。入选来源未通过后续检测时，最多再尝试两个不同网站补位，仍限最高分辨率，不无界扩展取样范围。
5. **保留失败和适用范围说明。** HDR 最高档可以展示规格，但当前不进行 HDR 模型评分，也不会因此自动降到较低分辨率；同站其他线路、低档、未进入前三站、无法对齐等均说明原因。规格预选序号不是最终画质名次。

## 不下载整集的体积估算

- 普通媒体优先读取 `HEAD` 响应头；必要时请求 `Range`，从 `Content-Length` 或 `Content-Range` 取得文件大小，及时关闭响应，不读取整集正文。
- HLS 先确定所选视频版本，再参考清单声明的平均码率、字节范围，或最多三个分片的响应头估算体积；读取播放清单，不下载视频分片正文。只有峰值码率时，不把它当作整集平均码率。
- 页面区分“已知体积”“估算体积”和“体积未知”，显示来源及是否包含音轨、封装开销等说明。大小估算有请求次数和时间上限，失败不会阻塞后续全部处理。
- 在同一集、相近时长、相同编码和相近帧率下，更大体积或更高视频码率可以作为预选依据；重编码、噪声、音轨和封装也会增大体积，因此它们不能代替最终模型评分。后续共同画面取样仍需读取少量实际视频数据。

## 排名的含义

- 最终分数来自真实的 MUSIQ 无参考画质模型，在本机 CPU 上推理。规格用于智能预选，不作为模型分数加权项，也不会把未经取样的线路排成画质冠军。
- 智能模式与全来源模型快速模式比较三个正文位置；全来源模型完整模式尝试四个位置。每个位置仍检查三个相邻画面，所有入榜来源必须拥有至少三个共同位置。三位置模式的取样覆盖少于完整模式，两次不同取样的分数不宜直接比较。
- 智能模式排名仅覆盖最高分辨率中入选且成功匹配的候选，不保证排除的低分辨率来源实际画质更差。全来源模型快速或完整模式不按分辨率淘汰，低分辨率高质量来源仍有取样和获胜机会。
- 智能模式每站只取一条预选线路；全来源模型模式中，网站名次依据其最佳已检测线路。表格保留各线路的规格、筛选和检测状态。
- 模型分数不是百分制正确率。**目前属于实验性画质估计，尚未完成动画领域人工校准。** 小幅分差不代表肉眼一定可见。
- 结果只代表所选这一集的抽样，不保证整集、整部作品或整个网站都保持同样画质；不评估音质、加载速度和全部运动伪影。
- 只有一个可比较网站、共同画面不足或内容不一致时不会生成跨站冠军；失败也不会记为零分。

## 当前兼容范围

- Kazumi XPath 和 API 规则（JSONPath、请求模板、嵌套及分隔字符串章节）。规则文件每次搜索重新只读加载。
- 使用本机 Microsoft Edge 的隔离无界面会话解析播放页和 iframe，不访问日常浏览器的登录会话。
- 支持 FFmpeg 可以读取且时长有限的公开视频流。直播、HDR、画幅明显不同、无法对齐的版本不纳入模型比较；HDR 可保留规格结果，智能模式不为此降低分辨率门槛。
- 局部时间偏移搜索窗口约 ±40 秒；更长片头差异、不同剪辑或强水印可能导致无法对齐。
- 验证码、登录、交互播放、特殊加密或失效规则可能不可用；在 Kazumi 中验证不会自动同步到助手。
- 首版不把 Cookie 或 Authorization 交给 FFmpeg。带有这些凭据的媒体会明确提示暂不支持，避免在重定向和跨域分片请求中错误转发。普通统计 Cookie 也可能触发此限制。
- 网站响应有大小和超时限制；正文含压缩流受总截止时间保护。体积估算可在超时或取消时中断慢速响应头；搜索与章节请求的异常慢速响应头仍不保证硬实时截止，首次模型加载也可能需要等待才响应取消。

## 性能与本地诊断

- 智能模式先探测全部已确认来源，再将体积估算限制在最高分辨率，将模型取样限制在前三站及最多两站补位；搜索、解析和规格探测仍受网站响应速度影响。
- 相邻三帧共用一次 FFmpeg 解码，保持原采样画面；用于内容匹配的中间图缩至192宽，实际评分仍使用完整取样图。
- 视频解析、规格探测与后续线路取样最多两路并发；CPU 模型三帧一批，共享模型串行执行。逻辑核心数至少12时最多使用8个推理线程，其余最多4个，避免无界争抢。
- 页面显示本次总耗时和每条线路的阶段耗时。阶段累计时间可能超过总耗时，因为有并行处理；“评分”也包括等待共享模型的时间。
- 每个阶段结束及任务完成时保存脱敏记录到 `data/diagnostics/`。只存站点、状态、规格、评分、耗时等字段，不保存规则、播放链接或凭据。页面底部可展开最近100份记录的诊断摘要；记录文件保留在本机，可在停止服务后自行清理。
- 运行下面命令汇总本机已有验证及诊断记录；旧版本未记录的耗时不能从启动日志还原：

```powershell
.\.venv\Scripts\python.exe -X utf8 tests/collect_diagnostics.py
```

先前版本的本地 HTTP 基准中，三帧提取中位数从0.540秒降至0.196秒，评分图像素一致；粗匹配PNG体积降低约95%。当时两次实际两站四线路快速检测耗时89.0秒与87.6秒。**这些是历史全来源检测与局部基准，不是当前智能模式实测，也不能据此保证其他网站的速度。** 模型短基准中三帧一批、8个线程均有收益，但真实任务仍受网络、解码及其他程序负载影响。

2026-09-09 智能模式实测：搜索全部 16 条规则用时 6.3 秒，确认 5 个同名网站、探测 14 条线路后，检测用时 254.0 秒。最终仅取样最高档的 3 个不同网站，三站均形成模型排名；2 条较低分辨率线路完全跳过体积估算与取样。规格和体积阶段约 147.4 秒，后续模型流程约 106.6 秒。源站解析仍占明显时间；历史完整模式的 465.4 秒使用不同网站范围和取样数量，不能据此承诺固定提速比例。

## 本地数据与仓库

以下目录已加入 `.gitignore`，不会上传 Git：

- `.runtime/`：本机独立 Python 解释器。
- `.venv/`：本工具专用依赖。
- `data/`：模型权重、配置、运行日志与验证记录。
- `.idea/`：本机 IDE 配置。

临时帧在检测完成或正常取消后清理。异常终止可能留下 `data/temp/` 下的临时文件，可以在停止工具后手动清理。来源视频和规则内容不上传到评分服务，首次准备依赖与模型需要联网下载。

## 从仓库重新安装

这台电脑的运行环境由当前工作完成配置。其他路径或机器需要 Python 3.12、PowerShell 7、Microsoft Edge，以及首次安装时的网络连接：

```powershell
pwsh -File .\setup.ps1 -PythonPath 'C:\Python312\python.exe'
```

如果本目录已有 `.runtime\python.exe`，可省略 `-PythonPath`。本机已配置的解释器、依赖和模型合计约 2 GB，其中 MUSIQ 权重约 104 MB；这些文件不会提交 Git。它不是单个很小的 DLL 插件。

## 开发与验证

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
node tests/test_ui_contract.js
.\.venv\Scripts\python.exe -X utf8 app.py --no-browser
```

手动公网验证脚本位于 `tests/verify_installed_sources.py` 和 `tests/verify_media_sources.py`，只在明确执行时读取本机规则并访问网站，结果写入被忽略的 `data/`。智能流程可运行 `.\.venv\Scripts\python.exe -X utf8 tests/verify_smart_flow.py --keyword '完整番剧名称' --episode 1`，检查全部规则、前三网站、补位上限和低档跳过；脱敏结果保存在 `data/智能比较实测.json`。单元测试使用临时文件、本地 HTTP 服务或固定响应，不修改实际 Kazumi 数据。
