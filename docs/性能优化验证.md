# 性能、准确性和界面优化验证

验证日期：2026-09-09。

## 完成范围

- 规则正文从逐字节改为64KiB读取，保留大小限制，并对慢正文及无解压输出的压缩流实施截止；响应头的异常滴流仍沿用 requests 的读取超时边界。
- 修复空白数字拼接为错误集号、重复条目和无效API播放链接；只统一明确的季号表达，不模糊预选续季或剧场版。
- 相邻三帧共用一次FFmpeg解码，验证真实PTS及像素一致性；匹配中间图缩至192宽。
- 两路有限并发，三帧批量推理；高核心数CPU上限8线程。默认快速三个位置，完整四个位置；两者都不按分辨率、码率淘汰来源。
- 按视频DAR/SAR判断显示画幅，避免误排除非方形像素的低分辨率宽屏视频。
- 增加阶段耗时、脱敏本地记录、异常退出记录恢复、刷新后活动任务恢复，以及用户来源选择恢复。
- 页面收起路径设置，新增排名概览、阶段耗时、日志摘要、第一名强调与窄屏卡片布局。

## 证据

Python完整测试99项通过；后续来源选择恢复的小改动另经6项调度测试与前端契约测试验证。日志汇总脚本5项自测、依赖检查、UTF-8扫描通过。

本地HTTP视频基准（3轮中位数）：相邻三帧从0.5401秒到0.1964秒，FFmpeg进程3次到1次，输出像素一致。82张匹配图PNG体积约13.92MB到0.68MB。

MUSIQ批次短基准：6帧、4线程，逐帧平均6.35秒、三帧一批平均4.40秒；最大分差0。线程短基准：三帧一批，4线程中位数2.246秒、8线程1.483秒，最大分差0。存在系统负载波动，不能推算固定整流程提速比例。

两次真实两站四线路快速检测分别89.0秒、87.6秒，均取得三个共同位置并形成跨站排名；第二次由实际浏览器界面发起。已检查同季预选、进行中刷新恢复、最终结果、第一名高亮。浏览器错误日志为空。

1440宽桌面与390宽窄屏布局经过浏览器检查，页面无横向溢出；窄屏结果行转换为卡片。检查结束后恢复原窗口尺寸。

旧版本启动日志没有保存每次检测及阶段耗时，无法还原用户所有历史任务。原始本机记录、详细汇总、基准JSON均留在被忽略的data目录，没有提交网站配置或媒体地址。

## 剩余限制

依赖网站验证码、登录或特殊解密的来源仍可能无法检测；失效站点不记作低分。未按分辨率筛掉来源意味着参与线路越多仍会增加耗时。CPU模型是实验性估计，快速取样覆盖少于完整模式，接近的分数需要复测或实际观看。
