# 性能与诊断优化计划

目标：减少重复联网和计算，保留低分辨率高画质来源，修复有证据的查询问题，并使今后的检测耗时可追溯。

用户已授权整体排查、修复和优化；继续在独立仓库实施，不修改 Kazumi。

## 证据与取舍

旧日志只有启动信息和开发时保存的几份结果，未持久保存用户每次任务及阶段计时。无法从这些记录还原所有历史检测或精确分配耗时，不能据此声称某站永久最快或最清晰。

目前每条线路串行，12 张取样各自启动 FFmpeg；粗匹配的低维指纹却先保存大尺寸 PNG；CPU 模型逐帧推理。规则正文单字节读取有性能问题，含空格数字的集数标签有误读风险。

采用以下方案：

- 分辨率、编码、可用码率用于规格展示与安排参考源顺序，不作为淘汰门槛。码率缺失不填零，不跨编码用码率阈值决定画质。
- 默认快速比较三个共同位置，每处仍检查三个相邻画面；完整模式取四处。所有可用来源仍有实际取样机会，不做“只看最高分辨率前几名”。
- 章节和规格有限并发，取样最多两条线路并发，模型串行受锁保护；避免网站请求和内存无界增长。
- 合并相邻取帧；粗匹配使用小尺寸图；同媒体和请求上下文只检测一次。
- 本地保存脱敏阶段计时、结果与错误。界面显示耗时，刷新后恢复当前任务。日志不记录规则、Cookie、令牌或签名媒体链接，不提交 Git。
